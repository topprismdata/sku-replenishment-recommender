# 零售SKU推荐竞赛：完整EDA指导手册

> 基于COFCO POC竞赛的实战经验，总结的EDA标准流程。
> 适用于任何零售/快消品推荐竞赛。
> 给所有AI agent使用。

---

## 核心理念

**EDA不是df.describe()，而是像人类分析师一样思考。**

每次分析必须：
1. 先有业务假设
2. 用数据验证（不是想当然）
3. 手工抽查真实案例（不能只看汇总统计）
4. 记录所有发现
5. 结论必须下沉到子渠道+线路层面

---

## 第一步：理解任务和数据格式

### 1.1 搞清楚任务定义
- 预测目标是什么？（SKU列表？购买概率？）
- 评测指标是什么？（F1？AUC？MAE？）
- 数据格式：submission的每行是什么含义？
- **关键陷阱**：recommend_date是"推荐日"还是"物理采购日"？（COFCO案例：是物理采购日，100%下单）

### 1.2 数据质量审计
```
□ orders: 行数、缺失值、重复行、负值（退货）、异常SKU
□ customers: 渠道字段、线路字段、客户性质字段、冰柜门数
□ products: SKU数量、GBHL聚合、ABC分类、在售状态
□ submission: 日期分布、周几异常、春节效应、任务量分布
□ 异常SKU: 不在products表的SKU（COFCO案例：6030前缀附属品）
```

### 1.3 Train vs Test对比
```
□ 客户重合率（冷启动占比）
□ 渠道分布差异
□ 测试客户的训练期活跃度画像
□ 时间分布差异（训练全年 vs 测试Q1）
```

## 第二步：建立业务知识

### 2.1 产品聚合粒度
- **不能直接用SKU码**：同产品有多个SKU（促销版/标准版/彩膜）
- 找到正确的聚合键（COFCO案例：GBHL = 品牌+口味+包装+瓶数）
- 验证：同聚合组内客户是否忠诚于某个SKU

### 2.2 渠道体系
- 搞清楚每个渠道/sales_chel_code/sub_chel的含义
- 大渠道（GT/MINI/餐饮）vs 子渠道（A51/B10/C21...）
- **渠道决定客户类型和采购模式**

### 2.3 线路（route_id）
- 线路 = 同一个销售员覆盖的客户群
- **线路是最强预测维度之一**
- 同线路客户采购高度同步（销售员统一配货）

---

## 第三步：逐子渠道深挖（核心步骤）

### 3.1 采样规则
**每个子渠道按频次分层采样40个客户：**
- 高频（>=30天下单）15个
- 中频（15-29天）15个
- 低频（5-14天）10个

**为什么是40个？**
- 高频15个：覆盖稳定客户的行为模式
- 中频15个：最容易暴露新模式（有足够数据但不至于像高频那样"什么都有"）
- 低频10个：验证低频客户的特殊性

### 3.2 每个客户必须查看的完整profile

```
对每个客户：
  □ 基本信息：子渠道、线路、冰柜门数、客户性质(DTC/DSS)
  □ 统计：下单天数、SKU数、GBHL数、购物篮中位、采购间隔中位
  □ 完整采购序列（按日期）：每次下单的GBHL列表
  □ SKU忠诚度：同GBHL内买几个SKU、top1占比
  □ Q1行为：2025 Q1的下单模式
```

### 3.3 四个维度分析

#### 维度1：产品
```
□ 该渠道TOP20 GBHL + 占比
□ ABC构成（A/B/C/其它占比）
□ Q1 vs Q3 季节性差异
□ SKU切换率最高的GBHL（CAN330ml系列等）
```

#### 维度2：线路
```
□ TOP10线路的客户数、订单量
□ 每条线路的"第一产品"（线路个性）
□ 线路主下单日（周几）
□ 线路SKU集中度（TOP5占比）
□ 同线路同日客户Jaccard（同步性验证）
```

#### 维度3：客户（五维分析）
```
□ 子渠道 × DTC/DSS
□ 历史购物频次 → 稳定性（前后Jaccard）
□ 客户类型分层：
  - 现调机DTC（BIB糖浆+气瓶+配件）
  - SleekCAN忠诚DTC
  - 瓶装DTC
  - DSS高频
  - DSS低频
```

#### 维度4：时间
```
□ 月度活跃度曲线
□ 周几分布
□ 春节效应（春节/普通比）
□ 春节 × 子渠道 × 线路（差异化影响）
□ 关键：2025春节≠2026春节，按月聚合而非周几
```

### 3.4 特殊分析

#### DTC/DSS配送方式（超级特征）
```
□ DTC客户买BIB的概率（vs DSS）
□ 按子渠道的DTC→BIB概率查表
□ DTC的三种子类型识别
□ 冷启动客户用DTC标签推断BIB需求
```

#### 线路×日协同信号（全渠道验证）
```
□ 所有子渠道的同线路同日客户Jaccard
□ 高同步线路（Jac>0.8）vs 低同步线路（Jac<0.4）
□ 线路同步性 = 线路级推荐策略的权重
```

#### 频率×稳定性四维分析
```
□ 渠道 × 频次 × 线路 × DTC/DSS
□ 每个组合的前后Jaccard（稳定性）
□ 最稳定组合（复制历史）vs 最不稳定组合（需协同）
□ 用户假设验证："频率越低稳定性越高"（分渠道不同！）
```

## 第四步：三种宽度分析（N推断依据）

**关键认知：单次购物篮中位 ≠ 推荐N**

客户Q1有3个月，多次采购，累计去重SKU远大于单次。

```
对每个子渠道 × DTC/DSS，计算三种宽度：
  □ 每次下单宽度（单次购物篮大小）中位
  □ Q1累计去重SKU数中位
  □ 全年累计去重SKU数中位

关系：
  每次宽度 << Q1累计 << 全年累计
  N应该 ≈ Q1累计（覆盖多次采购场景）
  N ≠ 每次宽度（太小）
  N ≠ 全年累计（太大，包含非Q1产品）
```

## 第五步：实验设计与验证

### 5.1 核心原则：一次只改一个变量

```
❌ 错误：同时改N和推荐内容来源 → 无法归因
✅ 正确：只改N（内容固定）或只改内容（N固定）
```

### 5.2 实验基线选择
```
□ 总是基于已验证最优版本叠加改进
□ 不要回到更早的基线重新开始
□ 每次实验的基线 = 上一次的最高分版本
```

### 5.3 提交前必须做假设

```
每次提交前：
  □ 预测哪个版本最好，为什么
  □ 预测大致分数范围
  □ 明确这个实验在验证什么变量
  □ 假设记录到文档

提交后：
  □ 对照假设 vs 实际结果
  □ 更新EDA和知识库
  □ 如果假设错误，分析为什么
```

### 5.4 抽查规则

```
每个提交版本必须抽查至少40条：
  □ SKU数量正确（=目标N）
  □ 无重复SKU
  □ 无空推荐
  □ 非目标客户零误改
  □ 推荐内容合理（手工看产品名）
  □ 和基准的前N个一致（如果是截取实验）
```

### 5.5 向量化优先

```
❌ 错误：逐客户循环327K行（要10+分钟）
✅ 正确：用pandas merge/groupby向量化（秒级）
□ 逐行apply也很慢，尽量用map+dict
□ 实在要循环，只循环目标客户子集（不是全部327K）
```

## 第六步：冷启动策略

### 6.1 冷启动客户分析
```
□ 占比（COFCO案例：13.2%）
□ 子渠道分布（哪个渠道冷启动最多）
□ DTC/DSS分布（DTC冷启动可推BIB）
□ submission任务数 = 频次信号
```

### 6.2 冷启动N优化
```
□ score_12教训：统一N vs 分渠道N
□ 冷启动推荐内容 = 渠道热销（按sales_chel_code）
□ N最优值需要A榜验证（COFCO：餐饮N=9，GT N=5）
□ 冷启动对整体F1影响小（13%客户 → 改N只变0.001）
```

### 6.3 冷启动天花板
```
□ 冷启动客户占比小（13%），优化空间有限
□ 应该在冷启动达到天花板后，转向有历史客户
□ 冷启动的天花板 = 分渠道最优N的版本
```

---

## 第七步：有历史客户优化

### 7.1 确认推荐来源
```
□ 当前有历史客户的推荐来自哪？（0.269参考文件？自研模型？）
□ 如果来自参考文件，需要自研模型替代才能优化
```

### 7.2 分层推荐模型
```
按EDA发现的客户类型分层：
  1. 现调机DTC（DTC+BIB）: 复制历史BIB套餐
  2. SleekCAN忠诚DTC: 个人历史SleekCAN组合
  3. 瓶装DTC: 个人历史+线路补充
  4. DSS高频: 个人历史为主+线路微调
  5. DSS低频: 线路×月热销为主+个人历史补充
```

### 7.3 五维特征
```
1. 子渠道（sub_chel）
2. 线路号（route_id）→ 线路×月Q1热销（排除春节）
3. DTC/DSS（customer_natur）
4. 历史购物频次（下单天数）→ 稳定性+N
5. 月份（Q1季节性）
```

### 7.4 AB对比实验
```
□ A组：概率统计模型（个人历史+线路热销融合）
□ B组：ML模型（LightGBM，五维特征）
□ 两组都基于同一个基准，只替换目标客户群
□ 同时提交对比
```

## 常见陷阱

### 数据陷阱
1. **GBHL的SKU选择规则**：不是价格最低，可能是渠道热销频次top1（促销版）
2. **春节月份错位**：2025春节(1/27) ≠ 2026春节(2/15)，按月不按周几
3. **空行不能删**：删空推荐行导致F1暴跌20倍
4. **submission日期是物理采购**：不是预测日，100%下单

### 实验陷阱
1. **一次只改一个变量**：同时改N和内容 → 无法归因
2. **基于最优版本叠加**：不要回到旧基线
3. **冷启动影响小**：13%客户，改N只变0.001
4. **向量化优先**：逐行循环327K行要10+分钟

### 认知陷阱
1. **单次购物篮中位 ≠ N**：N应该≈Q1累计去重SKU
2. **线路同步是普遍现象**：不只是某个渠道
3. **DTC ≠ 现调机**：DTC有三种子类型
4. **频率×稳定性是四维函数**：分渠道不同方向

## 节奏建议

1. **不要急**：每个子渠道认真看完40个客户再下结论
2. **不要跳**：中频客户最容易暴露新模式，不能跳过
3. **每次提交做假设**：让每次提交都有学习价值
4. **记录所有发现**：即使看似不重要的也要记录
5. **结论下沉到子渠道+线路**：不能停在全局汇总
